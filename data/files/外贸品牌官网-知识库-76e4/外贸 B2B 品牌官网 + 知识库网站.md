# B2B 品牌官网构建器 · 行业通用版 v1.0

> 本技能把任何外贸工厂的零散资料（店铺/官网/文件夹）变成一个
> 高端品牌官网，部署到 GitHub Pages 免费托管 + 全球 CDN 加速。
> 已在真实客户（台州爱以思 · 户外 PP 编织地垫）实战验证。

```
用户想做一个 B2B 品牌官网
```

GitHub 仓库一份，包含：

| 文件 | 用途 |

| `交接说明.md` | 给客户的中文操作手册 |

加上：GitHub Pages 启用 → 全球公开地址 `https://{user}.github.io/{repo}/`

## 3. 3 级访问权限（核心 — 必须严格按这个实现）

| URL | 谁能看 | 能做什么 |
|---|---|---|
| `https://{user}.github.io/{repo}/` | 客户 / 买家 | **只读**。不能看到任何"编辑"按钮，不能看到内部模块 |
| `https://{user}.github.io/{repo}/?staff` | 内部业务员 | 客户视图 + 多 2 个内部模块：**情报/画像** + **话术/SOP**。只读，软密码（`localStorage.{brand}_staff_ok="1"`）|
| `https://{user}.github.io/{repo}/?admin` | 老板 / 主管 | 上述全部 + **每个模块都能编辑/删除/新增**。令牌 = GitHub fine-grained PAT，存 `localStorage.{brand}_admin_token` |

**铁律：**
- `isAdmin()` 必须同时满足：URL 带 `?admin` 参数 **且** 本地有 token
- 业务员和管理员检测都是 URL 参数控制，客户截屏公开页绝不会看到任何"编辑"按钮
- localStorage 键名必须带品牌前缀（如 `aiyisi_lang`，不要光叫 `lang`），多品牌管理员在同一浏览器不会冲突

## 4. 标准导航（永远是这 4-6 项）

```
首页 | 认证资质 | 产品目录 | 合作品牌     [🌐 中文 ▾]
                                [+staff/admin 模式多 2 项：情报/画像 | 话术/SOP]
```

**禁用这些名字**（听起来很 low）：
- "Products" → 改用 **产品目录 / Catalog**
- "Cases" → 改用 **合作品牌 / Partner Brands**
- "About Us" → 用 **认证资质**（包含资质 + 关于我们）
- "品牌资产 / Brand Assets" → 直接砍掉（鸡肋栏目，无业务价值）

## 5. 首页必备模块（按这个顺序）

```
1. Hero 轮播             (3 张大图，21:9 宽屏，品牌主张 + 2 个 CTA)
2. 数据成就横条          (6 项：年限 / 厂区面积 / 出口比例 / 复购率 / 专利数 / 准时发货率)
3. Why-{品牌} 卡片矩阵    (5-6 张：高新企业 / 资质认证 / 全工艺 / OEM / 全球展会 / 亚马逊卖家友好)
4. 全球展会矩阵          (可点击 → 跳到展会详情页，含每届记录)
5. 三大产品线分类入口     (3 张：从每类前 3 款产品的图自动派生)
6. 客户 Logo 墙          (5-6 个零售商：Aldi/Lidl/Home Depot/Kmart/Metro/...)
7. 全球区域代理招商       (4 区域：北美 / 欧洲 / 大洋洲 / 中东)
8. 页脚                  (4 栏：品牌 / 联系 / 地址 / 能力)
```

**硬性要求：**
- Hero 图必须 **21:9 比例**。如果用户给方图，先用 AI 扩图到 21:9，**绝对不要硬裁**
- 数据成就横条的"年限"字段用动态公式：`当前年份 - 成立年份`（和阿里"12 YRS Gold"标识对齐）
- Why 卡片都要可点击 → 跳到相关栏目（认证/产品/展会）
- 客户 Logo 用品牌色文字兜底（外链失败不能露出破图）
- 页脚**绝不**出现 Alibaba 店铺链接 —— 本站就是品牌，不是供应商展示橱窗

## 6. 多语言架构（B2B 品牌必备）

**4 种语言：** `en`（新访客默认）、`zh`、`de`、`es`。
**为什么是 4 种？** 覆盖全球 B2B 买家 80% 的语种需求（北美+欧洲+西语市场），多了维护成本高。

**数据模型：** 每个面向用户的文本字段都是 `{en: "", zh: "", de: "", es: ""}` 结构。helper 函数：

```js
function L(v){
  if(v && typeof v==="object") return v[LANG] || v.en || v.zh || v.de || v.es || "";
  return v || "";
}
```

**语言切换器：** 折叠下拉（**禁止** 4 个按钮一排 — 占空间、显土）

```
🇨🇳 中文 ▾
   ┌──────────────┐
   │ 🇺🇸 English  │
   │ 🇨🇳 中文 ✓   │
   │ 🇩🇪 Deutsch │
   │ 🇪🇸 Español │
   └──────────────┘
```

**URL 强制切换：** `?lang=en|zh|de|es` 强制语言并写入 localStorage（用于二维码定向投放）

**自动翻译**（仅 admin 编辑用）：
- 主输入框 → 🌐 按钮 → 调谷歌翻译公开端点（无需 key） → 失败降级到 LibreTranslate
- 自动语种识别（字符正则）：含中文 → zh；含 ñáéí → es；含 äöüß → de；其余 → en

## 7. Admin 编辑能力 — 字段级覆盖

每个区块都必须在 `?admin` 模式下可编辑：

| 区块 | 编辑类型 | 字段结构 |
|---|---|---|
| Hero 轮播 | 列表（增删排序）| `{img, kicker:{4 语言}, title:{4 语言}, sub:{4 语言}, ctaPrimary:{4 语言}, ctaGhost:{4 语言}}` |
| 数据成就 | 列表（最多 6 项）| `{value, label:{4 语言}, _auto?:"years"}` |
| Why 卡片 | 列表（增删排序）| `{icon, title:{4 语言}, desc:{4 语言}, cta:{4 语言}, link}` |
| 产品分类 | 3 项 | `{img, title:{4 语言}, sub:{4 语言}, searchKey}` |
| 客户 Logo | 列表（增删排序）| `{name, img|file, bg, color}` |
| 区域代理 | 列表 | `{flag, name:{4 语言}, sub:{4 语言}}` |
| 区块标题 | 对象 | `{whyTitle, whySub, catsTitle, ..., contact, contactEmail}` |
| 产品 | 列表 | `{id, name, sku, price, moq, images[], video, specs[], detailImgs[]}` — 见第 8 节 |
| 资质认证 | 列表 | `{id, title:{4 语言}, desc:{4 语言}, image, verifyUrl, verifyLabel:{4 语言}}` |
| 展会矩阵 | 列表 + 每个展会 N 届 | 见第 9 节 |
| 合作品牌 | 列表 | `{name, logo, year, region}` |
| 话术/情报（内部）| 列表 | `{cat, t, c}` |

**编辑器 UX 铁律（血泪教训）：**
- ✅ 编辑弹窗每个 item 卡片顶部显示 **缩略图 + 自动派生的标题**（让 admin 一眼分清编辑的是哪个，**绝不只显示 "#1 #2 #3" 数字编号**）
- ✅ 每个多语言字段显示 **1 个主输入框 + 🌐 翻译按钮 + ▾ 展开手动改**（**绝不**一排 4 个输入框 — 看着头晕）
- ✅ 每个图片字段配 **📤 上传按钮**，上传到 `/uploads/u{时间戳}.{扩展名}`，URL 自动回填
- ✅ admin 模式下 hover 任何首页区块 → 出现蓝色虚线高亮 + 角落露 ✏️ 按钮
- ❌ 绝不做行内编辑（contenteditable）— 太脆弱，手机上显示一塌糊涂
- ❌ 绝不做"一个弹窗 30 个输入框"的胡乱堆砌 — 必须分组

## 8. 产品详情页 — 模仿阿里三段式规格布局

```
[图片轮播]                  | [基本信息表]
[置顶询价条]                | [包装与配送表]
                            | [描述参数表]
[滚动详情长图，admin 可上传]
```

**基本信息标准 11 字段**（根据行业调整）：
1. 产地（Place of Origin）
2. 材质（Material）
3. 工艺（Technics）
4. 特性（Feature）
5. 厚度（Thickness）
6. 形状（Shape）
7. 风格/图案（Pattern / Style）
8. 尺寸（Available Sizes）
9. 护理说明（Care Instructions）

**图片：** 多图上传（拖拽 / 粘贴 URL / 文件选择）。主图缩略图 + 大图轮播箭头。**每款限 10 张**。

**视频：** 只支持 YouTube 嵌入（**禁止**自托管视频 — 带宽噩梦）。字段填完整 YouTube URL，自动提取视频 ID。

## 9. 展会系统（B2B 信任度核武器）

展会是**一级实体**，不是首页装饰：

```
fairs: [
  {
    id: "canton-fair",
    name: {4 语言},
    location: {4 语言},
    description: {4 语言},
    poster: "url",
    editions: [
      {id, dateStart, dateEnd, booth, photos: [], notes:{4 语言}}
    ]
  }
]
```

**状态徽章**（根据届次日期自动算）：
- `Upcoming 即将参展`（日期 > 现在）
- `Live Now 正在参展`（现在介于开始/结束日之间）
- `Past 已参展`（日期 < 现在）

**为什么这块这么重要：**
海外买家不信任没有展会记录的供应商。一个可点击的、含真实展位照片的展会历史，
**转化询盘的效果比"我们经常参展"一句话强 3 倍**。

## 10. 技术栈 + 部署

**极简至上：**

| 层 | 工具 | 选这个的理由 |
|---|---|---|
| 托管 | GitHub Pages（免费）| 全球 CDN，无服务器月费 |
| 后台 | GitHub Contents API | token 授权 PUT 到仓库，相当于"免费 CMS" |
| 前端 | 纯 JS + CSS 内联到单个 `index.html` | 零构建，任何人能 fork 改 |
| 多语言存储 | 每字段 `{en,zh,de,es}` 对象 | 不依赖 i18n 库 |
| 自动翻译 | 谷歌公开端点 + LibreTranslate 兜底 | 免费、不需要 key |
| 图片托管 | 同仓库 `/uploads/`、`/hero/`、`/logos/`、`/textures/` | 自包含，不依赖 Cloudinary |
| 权限 | URL 参数 + localStorage 令牌 | 无后端 session，无数据库 |

**每个客户一次性部署步骤：**
1. 在自己的 GitHub 账号下建一个**公开**仓库
2. 推 4 类文件：`index.html` + `data.json` + `hero/` + `logos/`
3. Settings → Pages → 源选 `main` 分支 / root
4. 生成 fine-grained PAT，**只授权这一个仓库**，Contents 读写权限
5. 给客户 3 个 URL + 令牌（令牌走单独渠道）

**URL 长度优化：** 仓库名 ≤ 5 字符（如 `ays`，不要 `aiyisi-knowledge-base`）。客户手机要输入这个 URL。

## 11. 致命陷阱（不要重蹈覆辙）

| 陷阱 | 表现 | 怎么修 |
|---|---|---|
| **公开 URL 露出设置面板** | 客户看到 "Admin Token" 输入框 | `isAdmin()` 必须强制要求 URL 参数，不能光凭 token 存在 |
| **图片热链 CORS** | 客户 Logo 显示破图 | 自托管到仓库 `/logos/`，或回退到品牌色文字块 |
| **模板字符串里的撇号** | JS 解析报错 | 用 `&#39;` HTML 实体替代任何字符串里的撇号 |
| **搜索框失焦** | 客户输入卡顿 | 不要每次按键都重渲染整页；用 `oninput` + 单独列表刷新 |
| **年份卡死在起始年** | 网站老不更新，"12 YRS" 永远不变 | 用动态公式 `current_year - founded_year`，**禁止**写死 |
| **客户面网站写 "Alibaba supplier"** | 显得 low | 删除所有 Alibaba 痕迹。本站就是品牌，不是供应商展示橱窗 |
| **Hero 大图方形被裁切** | 主体上下被切一半 | 用户给方图必须先用 AI 扩到 21:9，**绝不直接裁** |
| **材质叠加层太重压糊用户图** | 用户上传图变模糊脏污 | 如要做 canvas 合成：叠加权重 ≤ 20%。更好的办法：直接用 AI 生成实景图 |
| **客户看不出弹窗里编辑的是哪条** | "#1 #2 #3" 数字编号 | 每个 item 卡顶部显示缩略图 + 自动派生标题 |
| **一排 4 个语言输入框** | admin 看着头晕 | 改成 1 主输入 + 🌐 翻译 + ▾ 展开 |
| **GitHub API SHA 冲突** | 报 "is at SHA X but expected Y" | 每次 PUT 前重新 GET 最新 sha |
| **CDN 缓存延迟** | 客户反馈"我没看到变化" | 让客户硬刷（Cmd+Shift+R）或加 `?t=N` 参数。CDN 1-3 分钟刷新 |
| **AI 图片生成网关 505** | 偶发失败 | 重试最多 3 次，间隔 3 秒。同样 prompt 通常重试就成功 |
| **仓库改名后令牌失效？** | 客户反映登录失败 | 令牌绑账号 ID 而不是仓库名，**改名不影响令牌**。但 Pages URL 变了 — 通知所有书签更新 |

## 12. 7 个核心提问（流程 D — 客户什么都没有时用）

用 `ask_user` 表单模式问，每次最多 4 题：

1. **公司中文 + 英文全称**
2. **成立年份 + 城市**（算年限 + 写页脚）
3. **主营品类**（一句话，如"户外 PP 编织地垫，出口为主"）
4. **目标市场**（多选：北美/欧洲/东南亚/中东/...）
5. **3 个最核心的卖点**（用于 Why 卡片）
6. **Top 5 零售客户名字**（用于客户 Logo 墙）
7. **销售邮箱**（用于页脚联系入口）

可选：

8. **Hero 大图风格**（给 3 选项："工厂生产场景" / "产品在生活方式中" / "全球布局地图"）

## 13. 技能边界（这些不做）

- ❌ 电商支付 / 结算（这是品牌目录，不是商城）
- ❌ 用户账号 / 询盘表单（故意不做 — 引导买家直发邮件，转化率高 40%）
- ❌ 自定义域名 / DNS 设置（给客户操作说明，**不要替客户做**）
- ❌ 搜索引擎 SEO sitemap / 结构化数据（建议作为 Phase 2）
- ❌ CRM 对接（超范围，业务员邮件回复即可）
- ❌ ERP 实时库存同步（目录是策划展示，不是实时库存）

客户提到这些 → 礼貌说明超出范围 + 报价 Phase 2。

## 17. 给执行 AI 的关键提醒

**做这类项目时，请遵守以下：**

1. **第一步永远是判断流程 A/B/C/D 并告诉用户** — 不要混走
2. **绝不静默假设** — 不知道公司全称、品牌色、目标市场等关键信息时，必须问
3. **每个 commit 都推 GitHub Pages 自动部署** — 不要本地试 N 次再一起推
4. **客户反馈说"不好看"时不要硬撑** — 立即回滚到上个 commit，问"具体哪里不好"
5. **多语言字段必须 4 语全填** — 哪怕 DE/ES 是用翻译引擎自动生成的也行
