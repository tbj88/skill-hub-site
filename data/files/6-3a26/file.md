# 海外客户背调全案 (Overseas Client Due Diligence)

把一整套海外 B 端尽调流程固化为一条可重复调用的流水线。给一个客户标识（公司名 / 官网 / LinkedIn / 邮箱 / 国别），自动按金额与风险选档，编排 6 个专用模块并行采集与核验，最终交付一份中英双语、带风险分级和合作建议的尽调报告。

## 设计哲学

外贸尽调的本质是**用可获取的公开信息，把"这个客户能不能合作、用什么条件合作"这个决策的不确定性压到最低**。真正的风险不是"信息缺失"，而是"把缺失当成了已知"。所以本技能的铁律是：**能查实的下结论，查不到的明确标"待人工补充"，绝不用推测填充空白冒充事实。**

## 能力边界（先声明，再动手）

每次执行前，先对用户言明哪些能真做、哪些受限于付费数据源。这不是免责，而是让用户知道报告里哪些结论是硬证据、哪些是间接推断。

| 模块 | 可落地程度 | 缺口说明 |
|---|---|---|
| ① 公开信息采集 | 大部分可做 | 官网/LinkedIn/FB/IG/whois/免费注册局可抓；**海关进出口记录**靠 ImportGenius/Panjiva 付费库，无接口，只能公开估算并标注 |
| ② 资质核验 | 部分可做 | 欧盟 VAT（VIES）✅、FDA✅、CE/ISO 查发证机构✅；美国 IRS 税号无公开校验❌、**离岸实控人穿透（BVI/开曼）不公开**❌ |
| ③ 风险黑名单 | 可做且可靠 | OFAC SDN、欧盟/联合国制裁名单公开可查；部分国家失信/破产记录公开 |
| ④ 商业信用 | 受限 | 邓白氏/Equifax 为付费征信，无账号；只能用营收规模、纳税公开数据做间接判断，**给不出正式信用分** |
| ⑤ 舆情社媒 | 可做 | Trustpilot、Google 评论、论坛、社媒活跃度 + 多语种情感分析 |
| ⑥ 报告整合 | 可做 | 多源去重交叉校验 + 风险分级 + 中英双语导出 |

**三个硬缺口固定标注"待人工补充（需付费库）"**：海关进出口明细、付费征信信用分、离岸公司实控人穿透。

## 第一步：解析输入，确认档位

从用户输入中提取客户标识。最少需要一个锚点（公司名 / 官网域名 / LinkedIn URL / 业务邮箱 / 国别其一）。锚点越多，交叉校验越准。

如果用户没说档位，按金额/账期/地区自动建议，并向用户一句话确认：

| 档位 | 适用场景 | 启用模块 |
|---|---|---|
| **轻度** | 小额新客户、首单试探 | ① 采集 + ⑤ 舆情 + ⑥ 报告 |
| **常规** | 标准外贸客户、常规订单 | ① 采集 + ② 资质 + ⑤ 舆情 + ⑥ 报告 |
| **全套** | 大额订单 / 长期代理 / 大额账期 | ①②③④⑤⑥ 全开 |
| **高危地区** | 中东 / 非洲 / 拉美客户 | ③ 风控 + ② 资质（实控穿透优先）打头，再 ①⑤⑥ |

> 主公默认偏好「全套」档位用于大额/长账期。无明确说明时，对大额或长账期客户默认走全套。

确认锚点与档位后，**不要再追问无关细节**，直接进入编排。

## 第二步：编排执行（并行优先）

按所选档位，用 `sessions_spawn` 并行启动对应模块（每个模块一个子代理，互相独立、各自自带锚点）。模块细则见 `references/modules.md`，执行前按需读取对应章节。

并行原则：①②③④⑤ 之间无依赖，应在同一轮全部 spawn 出去；⑥ 报告整合依赖前序结果，最后执行。

每个子代理的 task 必须自带：客户全部锚点、本模块的目标产出字段、数据源清单（见 modules.md）、"查不到就标待补充、严禁编造"的硬约束、以及把结果以结构化 markdown 返回。

子代理类型选择：
- 公开网页采集 / 制裁名单查询 / 舆情抓取 → `general`（可 web + browser + 文件）
- 登录态/JS 重渲染页面（如部分注册局、社媒后台）→ `browser`
- 纯检索核验（VIES、FDA、whois）→ `general` 或 `bash`（accio-mcp-cli / curl）

## 第三步：交叉校验与缺口盘点

所有模块返回后，先做一致性校验再写报告：
- **同一字段多源比对**：地址 / 成立时间 / 法人 / 经营范围在官网、注册局、LinkedIn 是否一致；不一致是重要风险信号，必须在报告里点名。
- **去重**：合并重复信息，保留最权威来源（注册局 > 官网 > 社媒）。
- **缺口清单**：列出所有"查不到"的字段，区分"客观不公开（需付费库）"与"本次未查到（可再查）"。

## 第四步：风险分级与合作建议

按 `references/report-template.md` 的评级矩阵给出 **低 / 中 / 高** 三级，并附**可执行的合作建议**（预付比例、账期上限、是否需信用证/担保）。评级必须有证据支撑——每一级背后列明触发该评级的具体事实。

## 第五步：输出报告

按 `references/report-template.md` 生成**中英双语**尽调报告。文档规范（主公红线）：
- 字体「微软雅黑」，正文左对齐；
- 严禁红色字体、emoji、ASCII 树状图；
- 风险等级用文字标注（低/中/高 Low/Medium/High），不用色块或图标；
- **优先导出 PDF**（涉及 Word/Excel/PDF 文档操作时，调度 `office-suite` 子代理，主流程不自行用脚本处理 .docx/.pdf）。

报告产出后，在对话里给一句话结论（评级 + 核心建议）+ 文件链接，不要把全文倒进聊天。

## 执行纪律

- **边界先行**：每次开工先声明本次能覆盖什么、缺什么，再动手。
- **证据优先**：所有结论可溯源；推断必须标"推断"。
- **缺口透明**：三个硬缺口固定标注，不假装有数据。
- **不过度采集**：按档位启用模块，轻度客户别全套上，省时省力。
- **熔断**：同一模块换关键词搜索 3 次仍无果，停止并在缺口清单标注，不死磕。

# 附录一：6 模块执行细则

# 6 模块执行细则

每个模块对应一个专用子代理。执行某模块前，把本章节对应内容拷进子代理的 task 描述，使其自带数据源与产出字段。所有模块共享一条铁律：**查得到才写，查不到标"待人工补充"，禁止编造。**

---

## 模块① 海外公开信息采集

**目标产出字段**：公司全称 / 曾用名、注册号、成立时间、注册地址 + 实际经营地址、法人/董事/股东、经营范围、官网、社媒矩阵（LinkedIn/FB/IG/X）、域名注册信息、参展记录、（海关进出口——付费缺口，仅公开估算）。

**数据源清单**：
- 官网：直接抓 About / Contact / Team 页，留意"成立年份、员工数、工厂/办公地址、主营产品"。
- LinkedIn 公司主页：员工规模、行业、总部、动态活跃度。个人页可定位决策人。
- Facebook / Instagram 企业主页：经营活跃度、产品线、客户互动。
- 域名 whois：注册时间（与公司声称成立时间比对）、注册人、注册国。用 `whois <domain>` 或在线 whois。
- 各国免费企业注册局（重点）：
  - 英国 Companies House: https://find-and-update.company-information.service.gov.uk/
  - 美国各州务卿（州级）：如 CA `bizfileonline.sos.ca.gov`、DE `icis.corp.delaware.gov`、FL `dos.fl.gov/sunbiz`
  - 欧盟 e-Justice 商业登记门户：https://e-justice.europa.eu/
  - 新加坡 ACRA / BizFile（部分免费）：https://www.bizfile.gov.sg/
  - 澳大利亚 ABN Lookup: https://abr.business.gov.au/
  - 印度 MCA: https://www.mca.gov.in/
- 参展记录：搜行业展会官网 exhibitor list（如 Canton Fair、Ambiente、CES 等）+ "公司名 + exhibitor / booth"。

**反爬与多语言**：注册局/社媒可能需登录态或 JS 渲染 → 用 browser 子代理；非英语页面先抓原文再翻译，保留关键原文（地址、法人名）。

**缺口标注**：海关进出口明细统一标"待人工补充（需 ImportGenius/Panjiva 等付费库）"，可在报告里用公开新闻/参展/官网客户案例做定性估算。

---

## 模块② 跨境企业资质核验

**目标产出字段**：VAT/EORI 真伪、税号/工商备案状态、行业认证真伪（CE/FDA/ISO/医疗器械等）、离岸公司实控人（穿透缺口）。

**数据源清单**：
- 欧盟 VAT 校验（VIES，官方免费）：https://ec.europa.eu/taxation_customs/vies/ —— 输入国别+VAT号返回有效性+注册名。
- 欧盟 EORI 校验：https://ec.europa.eu/taxation_customs/dds2/eos/eori_validation.jsp
- 美国 FDA 注册查询：https://www.accessdata.fda.gov/scripts/cdrh/cfdocs/cfRL/rl.cfm （器械/食品企业注册）
- CE / ISO：CE 自我声明居多，重点核"发证机构（Notified Body）是否真实存在"+ 证书编号能否在发证机构官网查到；ISO 证书核发证机构是否 IAF 成员认可。
- 英国/欧盟公司状态：用模块①注册局确认 active / dissolved。
- 离岸（BVI/开曼/塞舌尔）：注册存在性可查，**实控人基本不公开** → 标"待人工补充（需付费穿透服务或当地代理）"。

**核验逻辑**：资质"存在"不等于"匹配本客户"——必须核对证书上的公司名/地址与客户一致；不一致即风险信号。

**缺口标注**：美国 IRS EIN 无公开校验、离岸实控穿透 → 固定标缺口。

---

## 模块③ 全球商事风险风控（黑名单筛查）

**目标产出字段**：是否命中制裁/失信/诉讼/破产/欺诈名单，关联企业风险连带。

**数据源清单（均公开）**：
- OFAC SDN 制裁名单（美国财政部）：https://sanctionssearch.ofac.treas.gov/
- 欧盟制裁名单（EU Sanctions Map / consolidated list）：https://www.sanctionsmap.eu/
- 联合国安理会制裁名单：https://www.un.org/securitycouncil/content/un-sc-consolidated-list
- 英国 OFSI 金融制裁名单、各国本地制裁名单（按客户国别补充）。
- 法院/破产：英国 The Gazette（破产公告）、美国 PACER（部分付费）、各国本地法院公开判决。
- 商业欺诈曝光：行业论坛、外贸黑名单社区、Google "<公司名> scam / fraud / 拖欠"。

**关联穿透**：对命中或可疑主体，查母子公司、同一法人/地址下的其它公司，评估风险连带。

**判定**：制裁名单命中 = 一票否决（高风险，不可合作）；失信/诉讼/欺诈曝光按严重度计入评级。

---

## 模块④ 海外商业信用评估

**目标产出字段**：资金/经营规模、付款履约能力间接判断、历史拖欠/仲裁记录。

**现实约束**：邓白氏（D&B）、Equifax、本地征信局均为**付费征信**，无账号 → **给不出正式信用分**。本模块走"间接信用画像"：
- 营收/规模：官网、LinkedIn 员工数、新闻报道、行业榜单、招股书（上市公司）。
- 纳税/财报：上市公司查年报（SEC EDGAR `https://www.sec.gov/edgar`、英国 Companies House 财报）。
- 历史拖欠/仲裁：复用模块③的诉讼/论坛曝光结果。
- 经营年限 + 规模 + 公开履约记录 → 给"信用画像（强/中/弱）"而非数字分，并说明依据。

**缺口标注**：正式第三方信用分固定标"待人工补充（需邓白氏/Equifax 付费报告）"。

---

## 模块⑤ 多语言海外舆情社媒

**目标产出字段**：口碑情感倾向、经营活跃度、负面预警（拖欠/虚假合作/跑路投诉）、上下游评价。

**数据源清单**：
- Trustpilot、Google 评论/Google Maps、行业垂直论坛、Reddit。
- 社媒动态频率：LinkedIn/FB/IG 最近发帖时间——**长期无更新 = 皮包公司高概率信号**。
- 多语种（英/西/法/阿/葡）：抓原文 → 情感分析（正/中/负）→ 保留代表性原文+译文。
- 负面关键词扫描：scam / fraud / complaint / unpaid / 拖欠 / 跑路 / 虚假 + 公司名/品牌名。

**输出**：情感倾向占比 + 经营活跃度判断 + 负面证据清单（带链接）。无明显舆情也要写"未发现公开负面"，不是留白。

---

## 模块⑥ 尽调报告整合

不单独采集，负责把①~⑤结果汇总。执行步骤见 `report-template.md`。核心动作：多源去重 → 交叉校验（标出矛盾点）→ 分模块填充 → 风险分级 → 合作建议 → 中英双语导出 PDF。

# 附录二：报告模板与风险评级

# 尽调报告模板与风险评级

## 风险分级矩阵

综合 6 模块结果给出 **低 / 中 / 高** 三级。评级遵循"就高不就低"——任一硬否决项命中即为高风险。

| 等级 | 触发条件（满足任一即归此级，就高不就低） | 合作建议 |
|---|---|---|
| **高风险 High** | 命中制裁名单（一票否决）/ 离岸空壳无实控 + 无经营痕迹 / 资质造假（证书查无） / 多起拖欠跑路曝光 / 社媒长期停更且无任何可核验经营信息 | 不建议合作；若必须，仅接受 100% 前 T/T 或不可撤销信用证，禁授信账期 |
| **中风险 Medium** | 信息部分缺失但无负面 / 成立时间短（<2 年） / 规模小且征信缺口 / 个别负面舆情未证实 / 多源信息有矛盾待澄清 | 谨慎合作；预付 50%~70%，余款见提单 copy；首单不给账期，复购后视履约逐步放宽 |
| **低风险 Low** | 资质齐全可核验 / 经营 3 年以上且活跃 / 无任何制裁失信负面 / 多源信息一致 / 有公开客户案例或参展记录 | 正常合作；可接受预付 30% + 尾款，复购客户可议 OA 30~60 天账期 |

**评级铁律**：每个等级背后必须列出触发它的**具体事实**（哪条名单、哪个缺失字段、哪起曝光），不能只给结论。

## 报告结构（中英双语）

每个模块中文段落后紧跟英文对照（或左右栏）。结构如下：

```
# 海外客户尽调报告 / Overseas Client Due Diligence Report
客户名称 Client | 报告日期 Date | 档位 Tier | 综合评级 Overall Rating

## 0. 摘要 / Executive Summary
- 一句话结论：评级 + 核心合作建议（预付比例/账期）
- 三大关键发现 Top 3 findings
- 硬缺口提示 Data gaps (待人工补充项)

## 1. 基础信息 / Company Profile（模块①）
公司全称·注册号·成立时间·地址·法人股东·经营范围·官网社媒·参展记录
[海关进出口：待人工补充，附公开估算]

## 2. 资质核验 / Qualification Verification（模块②）
VAT/EORI·税号状态·行业认证真伪（逐项：证书号 / 发证机构 / 核验结果）
[离岸实控/IRS：待人工补充]

## 3. 风险筛查 / Risk & Sanctions Screening（模块③）
制裁名单结果·失信诉讼破产·欺诈曝光·关联企业连带

## 4. 商业信用 / Commercial Credit（模块④）
规模营收·经营年限·履约记录·信用画像（强/中/弱 + 依据）
[正式信用分：待人工补充，需付费征信]

## 5. 舆情口碑 / Reputation & Sentiment（模块⑤）
情感倾向占比·经营活跃度·负面证据清单（带链接）·上下游评价

## 6. 综合评级与合作建议 / Rating & Recommendation
- 评级：低/中/高 Low/Medium/High（列触发事实）
- 合作条件：预付比例 / 账期上限 / 是否需 LC 或担保
- 跟进动作：建议的下一步核验或商务动作

## 附录 / Appendix
- 数据来源清单（每条结论可溯源）
- 缺口清单（区分"客观不公开"与"本次未查到"）
- 交叉校验矛盾点 Discrepancies
```

## 文档与归档规范（主公红线）

- 字体「微软雅黑」，正文左对齐。
- 严禁红色字体、emoji、ASCII 树状图。
- 风险等级纯文字标注（低/中/高 Low/Medium/High），不用色块/图标渲染。
- **优先导出 PDF**；涉及 .docx/.xlsx/.pdf 生成或编辑，调度 `office-suite` 子代理处理，主流程不自行用脚本生成办公文档。
- 归档：参照单询盘分析习惯，存至 iCloud 文稿对应背调目录（如无指定，存工作区并给出文件链接）。

## 交付话术

报告完成后，对话里只给：综合评级 + 一句话核心建议（预付/账期）+ 文件链接 + 硬缺口提示。不把全文倒进聊天。
